# Beyond Why website: working notes for Claude

Decisions for the Explorations + Builds rebuild. Update this file whenever a
decision is made. Items under "Open decisions" need Madhav's answer before any
code depends on them.

## How we work

- A separate Claude (the overseer) plans each step and reviews the result.
  Claude Code builds one step per prompt, on its own branch, and reports back.
- Never force-push, rewrite history, delete branches, or commit secrets.
- Never run migrations or data scripts against the production database.
- Stop and report when something doesn't match what a prompt expects.
- Every step ends with `npx tsc --noEmit` and `npm run build` passing.

## Repo and branches

- Repo: Beyond-Why/bw_deploy. Vercel serves beyondwhy.org from it.
- `main` = the live site. Only urgent fixes go there; they get merged into `v2`.

## Stack (fixed)

- Next.js 15 App Router, React 19, TypeScript. Node 22.
- CSS Modules; design tokens in `src/app/globals.css`. No Tailwind.
- Content is MDX on the filesystem (`gray-matter` + `next-mdx-remote/rsc`).
- Drizzle + Supabase (Postgres + Auth). Likes, bookmarks, reading progress,
  comments and polls already work: reuse them, don't rebuild them.
- One new dependency allowed: `@xyflow/react` (React Flow, MIT), loaded only
  on the exploration trail view via `next/dynamic`.

## Content model

- Deep Dives -> Explorations. Insight Cards -> retired (code removed).
  Builder Logs -> Builds.
- An exploration is a folder `src/content/explorations/<slug>/`:
  - `log.md`: written by hand while learning, one line per step.
  - `index.mdx`: the story view, frontmatter `id` = permanent UUID.
  - `trail.json`: generated by `npm run trail -- <path>/log.md`
    (`scripts/log-to-trail.js`). Never edit by hand except `layout`.
- `src/lib/trail.ts` is the source of truth for the trail shape:
  step kinds `question | source | deadEnd | insight | experiment | now | openThread`;
  link labels `led me to | went deeper | contradicted | tested in | so I think | opened | reframed`.
  Steps are numbered from 1 and never renumbered after publishing.
  `summary.sources` counts dead-end sources too.
- Format guide: `docs/trail-format.md`. Test fixture:
  `scripts/fixtures/sample-trail/`.
- Resources come from each trail's `resources[]` (deduped by `key`).
  `/resources/[id]` pages are built from all trails at build time; no
  database table until stage 2. URL id from key:
  `youtube:X` -> `youtube-X`, `isbn:X` -> `isbn-X`, `arxiv:X` -> `arxiv-X`
  (`/` and `.` become `-`), `note:X` -> `note-X`, and `doi:`/`url:` ->
  `doi-`/`web-` + the first 10 hex characters of sha1(key).
- A build is a folder `src/content/builds/<slug>/`: `index.mdx` (overview,
  milestones with dates, parts, files, kit) plus `logs/NN-<slug>.mdx`
  (dated logs with expected / happened / broke), linking exploration slugs.
- Every content entity keeps a permanent UUID `id` in frontmatter
  (`scripts/validate-content.js` enforces it).

## Routes

- `/explore`, `/explore/[slug]` (`?view=trail` for the canvas),
  `/builds`, `/builds/[slug]`, `/resources/[id]`.
- Permanent redirects: `/deep-dives/...` -> `/explore/...`,
  `/builder-log/...` -> `/builds/...`, `/insight-cards/...` -> `/explore`.
  Generated in `scripts/content-routes.js`, so old shared links keep working.

## Homepage (top to bottom)

1. Current hero, unchanged (pointed at an exploration).
2. Most Popular: explorations only.
3. One build as a full-width banner (at least 60vh, blends into the
   background, not a card): status, latest log, explorations behind it.
4. Rows of explorations under rotating headings; more load on scroll; nothing
   repeats; ends on "the edge of the map": open threads readers vote on.
